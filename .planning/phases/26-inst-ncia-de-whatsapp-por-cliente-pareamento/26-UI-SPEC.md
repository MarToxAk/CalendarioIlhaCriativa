## Spacing Scale

Tailwind default 4px-based scale. Values in active use across the admin panel — this phase adds nothing new:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px (`gap-1`, `p-1`, `mt-1`) | Icon-to-label gaps, badge inner padding |
| sm | 8px (`gap-2`, `space-y-2`, `mb-2`) | Compact stacks (arte-row style lists), badge groups |
| md | 12px (`gap-3`, `space-y-3`, `pb-3`, `px-3`) | Action-bar gaps, secondary-button padding, `<dl>` rows |
| md+ | 16px (`space-y-4`, `mt-4`, `px-4`, `py-4`) | Card-to-card gap, inter-field spacing |
| lg | 24px (`p-6`, `mb-6`, `space-y-6`) | Card interior padding, page-header margin |
| xl | 32px (`py-8`) | `<main>` vertical padding (layout-owned) |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px (`py-16`) | Full-card empty state vertical padding (matches `clients#index` empty state) |

**Exceptions (all pre-existing in the codebase, carried verbatim — do not introduce others):**
- `gap-1.5` (6px) — icon+label inside text-only affordances (e.g. "Rotacionar token" link). Reuse for "Forçar verificação" if rendered as a text affordance.
- `py-0.5` (2px) + `text-[10px]` — compact micro-badge only, matching `client/shared/_arte_status_badge.html.erb` compact branch. Used for the `clients#index` dot row label if any.
- Interactive element heights: `h-8` (32px) tertiary, `h-9` (36px) secondary, `h-10` (40px) primary, `h-11` (44px) text inputs. All multiples of 4; `h-11` is the touch-target floor for inputs.

## Typography

Contract pair: **regular 400** + **semibold 600**. `medium 500` is permitted ONLY where a new element sits directly beside an existing one that already ships at 500 (buttons, table `<th>`, form `<label>`) — matching, not expanding, the system.

| Role | Size | Weight | Line Height | Applied to |
|------|------|--------|-------------|------------|
| Display | 24px (`text-2xl`) | 600 | 1.2 (`leading-tight`) | Not used here — `clients#show` has no `<h1>` (page title lives in the topbar via `content_for :page_title`) |
| Heading | 14px (`text-sm`) | 600 | ~1.4 (default) | "WhatsApp" card `<h2>`, modal title (`text-base`/16px 600 for the modal only, matching `_confirm_modal`) |
| Body | 14px (`text-sm`) | 400 | 1.5 (default) | State description, `last_checked_at`, adoption explainer, error text |
| Body-emphasis | 14px (`text-sm`) | 600 | 1.5 | Inline emphasis inside warnings (`<strong>` — e.g. "Atenção") |
| Label | 14px (`text-sm`) | 500 | ~1.4 | `<dt>` labels in the state `<dl>` ("Estado", "Última verificação", "Pareado em") |
| Micro-label | 12px (`text-xs`) | 500 | ~1.4 | Meta text, `clients#index` column header, "pareado há X dias" caption |
| Badge | 12px (`text-xs`) | 500 | 1 | Connection-state pill label |
| Micro-badge | 10px (`text-[10px]`) | 500 | 1 | `clients#index` compact state label beside the dot (optional) |

Body copy uses Tailwind's default line-height (1.5 for `text-sm`). Warning banners use `leading-relaxed` to match `_confirm_modal` body.

## Color

60 / 30 / 10 split is already established by the admin panel and defined as CSS custom properties in `app/assets/stylesheets/application.css` (`:root`).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F9FAFB` (`bg-gray-50`) | Page background (layout-owned) |
| Secondary (30%) | `#FFFFFF` surface + `#E5E7EB` border (`border-gray-200`) + `shadow-card` | The WhatsApp card and every panel inside it |
| Accent (10%) | `#0F7949` (brand dark green; hover `#0a5c37`) | Primary CTA "Criar instância", focus rings (`focus:ring-[#0F7949]/20 focus:border-[#0F7949]`), text links ("Ver", inline nav) |
| Destructive | `#EE3537` (coral; hover `red-700`) | Reserved — see note. No hard-delete in this phase; used only as the `danger` modal variant color IF re-pair is framed as destructive (it is NOT — use `warning`). Effectively unused this phase. |

**Accent (`#0F7949`) is reserved for, and ONLY for:**
1. The single primary action per view — "Criar instância" (empty state) — button fill.
2. Focus ring / focus border on any interactive control.
3. Text hyperlinks that navigate (e.g. a "Ver arte" style link), at `text-[#0F7949] hover:underline`.

Accent is **never** used for: the connection-state badges, the QR frame, secondary buttons, the ban-risk banner, or the recency caution.

**Semantic colors (from `:root`, not counted in the 10% accent budget — status signaling only):**

| Semantic | Fill / Text / Border | Applied to |
|----------|----------------------|------------|
| Success `#14A958` | `bg-[#F0FDF4]` / `text-[#14A958]` / `border-[#14A958]/20` | `connected` state badge + dot (mirrors the "Ativo" client badge exactly) |
| Warning `#F59E0B` | `bg-[#FFFBEB]` / `text-amber-800` / `border-[#F59E0B]/20` | `awaiting_qr` state badge + dot; **ban-risk banner (PAIR-07)**; **recency caution < 7 days (PAIR-08)** |
| Error `#EE3537` | `bg-[#FEF2F2]` / `text-[#EE3537]` / `border-[#EE3537]/20` | `disconnected` state badge + dot; inline error text when the synchronous check or QR refresh fails |
| Neutral `#475569` | `bg-slate-100` / `text-slate-600` / `border-slate-200` | `unpaired` state badge; hollow/grey dot on `clients#index` when the client has no instance |

**Connection-state → color map (canonical — planner and executor use verbatim):**

| `connection_state` | Evolution source | Label (pt-BR) | Dot / badge palette |
|--------------------|------------------|---------------|---------------------|
| `unpaired` | (no instance / never connected) | `Sem instância` (index dot) / `Aguardando criação` (show) | Neutral `#475569` — hollow dot `border border-slate-300` (no fill) on index |
| `awaiting_qr` | `connecting` | `Aguardando pareamento` | Warning `#F59E0B` — solid amber dot |
| `connected` | `open` | `Conectada` (+ `(adotada)` suffix when adopted) | Success `#14A958` — solid green dot |
| `disconnected` | `close` | `Desconectada` | Error `#EE3537` — solid red dot |

Dot spec for `clients#index`: `inline-block w-2 h-2 rounded-full` + the fill class above, wrapped in a `<span>` with `title="<label>"` and an `aria-label` for screen readers. Column header: `Conexão` (`text-xs font-medium text-slate-500 uppercase tracking-wide`), `w-[90px]`, centered — matches the existing "Status" column.

## Copywriting Contract

All copy pt-BR. Verbs are imperative. No exclamation marks except the `⚠`/`Atenção` lead-in already used in `_confirm_modal`.

| Element | Copy |
|---------|------|
| Primary CTA (no instance yet) | `Criar instância` |
| Secondary — manual check (PAIR-05) | `Forçar verificação` |
| Secondary — QR manual regen (PAIR-03) | `Gerar novo QR` |
| Secondary — re-pair (connected/disconnected instance) | `Parear novamente` |
| Secondary — adopt existing (PAIR-02, shown when create hits "name in use") | `Adotar instância existente` |
| Empty state heading (client `has_one :whatsapp_instance` is nil) | `Nenhuma instância de WhatsApp` |
| Empty state body | `Crie uma instância para parear o número deste cliente. Sem instância pareada, este cliente não pode receber disparos.` |
| Awaiting-pair helper (above the QR, below the ban banner) | `Abra o WhatsApp no celular do cliente, toque em Aparelhos conectados e escaneie o código abaixo. Ele é atualizado sozinho a cada ~20 segundos.` |
| QR expired / rotation stopped | `O código expirou. Clique em "Gerar novo QR" para continuar o pareamento.` |
| Connected (fresh pair) | `Conectada. Pareado agora há pouco.` |
| Connected (adopted, Evolution returned `open`) | `Conectada (instância adotada). O webhook foi reapontado para este sistema.` |
| Adopted but not open | `Instância adotada, mas ainda não conectada. Escaneie o QR abaixo para parear.` |
| Last-checked line | `Última verificação: há {N} min` · `há pouco` when < 60s · `há {N} h` when ≥ 60min. Never a raw timestamp in the primary line; full timestamp goes in a `title=` attribute. |
| Paired-age line (PAIR-08, ≥ 7 days) | `Pareado há {N} dias neste sistema.` |
| Paired-age caution (PAIR-08, < 7 days) | `Pareado há {N} dia(s) neste sistema. Números pareados há menos de 7 dias têm mais risco de bloqueio — evite grandes volumes de disparo agora. A contagem começa no pareamento aqui e não reflete a idade real do número no WhatsApp.` |
| Ban-risk banner (PAIR-07 — amber, above the QR, always visible, no checkbox) | `Atenção: automatizar mensagens pelo WhatsApp pode levar ao banimento do número. Pareie apenas um número que a agência pode perder e vá com calma no volume de envios, principalmente nos primeiros dias.` |
| Error — synchronous check failed (`Evolution::Errors::Transient` / `Unknown`) | `Não foi possível falar com o WhatsApp agora. O estado acima pode estar desatualizado. Tente "Forçar verificação" de novo em instantes.` |
| Error — check failed, instance not connected (`Evolution::Errors::NotConnected`) | `A instância respondeu como desconectada. Use "Parear novamente" para reconectar o número.` |
| Error — QR refresh failed | `Não foi possível atualizar o QR Code. Clique em "Gerar novo QR" para tentar outra vez.` |
| Error — create failed (`Evolution::Errors::Permanent`) | `Não foi possível criar a instância no WhatsApp. Verifique a configuração do Evolution e tente de novo.` |
| Toast — check succeeded, state unchanged | `Conexão verificada: {label}.` |
| Toast — check succeeded, state changed | `Estado atualizado: agora {label}.` |
| Toast — instance created | `Instância criada. Escaneie o QR Code para parear.` |
| Toast — instance adopted | `Instância existente adotada e webhook reapontado para este sistema.` |
| Destructive confirmation — "Parear novamente" | Modal (`_confirm_modal`, `confirm_variant: "warning"`). Title: `Parear novamente`. Body: `Parear novamente encerra a sessão atual do WhatsApp deste número. Os disparos ficam indisponíveis até um novo pareamento ser concluído.` Confirm label: `Parear novamente`. Cancel label: `Manter conexão atual`. |

**Adoption flow copy note:** adoption is not a separate destructive action — it is offered inline after `Criar instância` returns the Evolution "name already in use" error. Render a warning-toned inline note (`text-sm text-slate-600`, no banner chrome) next to the `Adotar instância existente` button: `Já existe uma instância com este nome no Evolution. Adotar reaproveita essa instância e aponta o webhook para este sistema.`

## UI Considerations

Applicable state considerations resolved: **8 covered, 1 backstop, 0 unresolved**

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | client with no `whatsapp_instance` (show) | ✅ covered | Renders the empty-state card — heading + body from Copywriting Contract + single `Criar instância` primary button. Full-card layout mirrors `clients#index` empty state (centered, `py-16`, muted icon optional). |
| empty | client with no instance (index row) | ✅ covered | Hollow neutral dot (`border border-slate-300`, no fill) with `title="Sem instância"` — never a blank cell; the "zero" of zero-one-many is visually explicit. |
| loading | `Forçar verificação` (synchronous, in-request) | ✅ covered | Button enters disabled state with label `Verificando…` for the duration of the blocking request (`READ_TIMEOUT_FAST=15s` ceiling). No spinner library — text swap only. Page re-renders server-side with fresh `connection_state` + `last_checked_at`. |
| loading | QR image, first fetch pending | ✅ covered | `<img>` slot shows a `bg-gray-50 border border-gray-200 rounded-lg` square (≈`w-64 h-64`) with centered `text-sm text-slate-500` `Gerando QR Code…` until the first `refresh_qr` returns `qr_base64`. |
| error | Evolution timeout / unreachable on forced check or QR refresh | ✅ covered | Inline `text-sm text-[#EE3537]` message (copy in Contract) rendered inside the card below the state row. State badge and `last_checked_at` are NOT advanced on failure. Also fires the failure toast. |
| populated | all 4 connection states on show | ✅ covered | Each renders the state `<dl>` (Estado / Última verificação / Pareado em) + the matching badge palette from the connection-state color map. `connected` adds the fresh-pair or adopted line; `awaiting_qr` reveals the QR block; `disconnected`/`connected` reveal `Parear novamente`. |
| partial | `connected` but `paired_at` < 7 days | ✅ covered | Amber caution paragraph (PAIR-08 copy) appended under the state `<dl>`; no control is disabled — advisory only. |
| partial | adopted instance, Evolution returned a non-`open` state | ✅ covered | Shows the "Instância adotada, mas ainda não conectada" line + the QR block for re-pair (Copywriting Contract). |
| stale | webhook never delivered — displayed state is old | ✅ covered | `Última verificação: há N min` is always visible (with full timestamp in `title=`), and `Forçar verificação` is the always-available escape hatch (PAIR-05). Staleness is legible, never hidden. |
| overflow / long-text | `instance_name` (`livia_client_<id>`) display | 🧪 backstop | Deterministic and short (`livia_client_` + integer). If surfaced, render `font-mono text-xs text-slate-500 truncate`. Held-out visual check that a 4–5 digit client id does not wrap the card header. |
| zero-one-many | index column across 10–30 clients | ✅ covered | One `w-2 h-2` dot per row in a fixed `w-[90px]` centered column; no wrap, no truncation, no pagination impact. Mirrors the existing "Status" column footprint. |

QR rotation lifecycle (PAIR-03): the Stimulus controller polls `refresh_qr` every ~20s for ~2 min (≈6 codes), swapping the `<img src="data:image/png;base64,…">` each cycle; it stops and reveals `Gerar novo QR` on timeout, and stops + triggers a server re-render (card flips to the `connected` view) as soon as a poll returns `state === "connected"`. The base64 payload is never written to any log (INFRA-04).
