Output: the nested route, `Admin::DivulgacoesController#resend`, `resend.turbo_stream.erb`, the conditional `_grupo_row` button + `just_resent` note, and controller tests.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser form POST (admin session + CSRF token) → `#resend` | `button_to` submits a `POST` with the Rails authenticity token; the action mutates a `divulgacao_grupos` row and enqueues a job. |
| `#resend` → ActiveJob enqueue | The controller hands `@dg` to `Whatsapp::SendToGroupJob.perform_later`; all network I/O happens later in the job process. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-30-05 | Elevation of Privilege / IDOR | `#resend` `params[:divulgacao_id]` + `params[:id]` | high | mitigate | Both ids are re-resolved through `@client.divulgacoes.find(params[:divulgacao_id]).divulgacao_grupos.find(params[:id])` — a cross-client or stale id raises `ActiveRecord::RecordNotFound` → Rails 404, never a bare `DivulgacaoGrupo.find`. Regression test drives a client-A admin session at a client-B divulgação / group and asserts 404 with no client-B data in the body. |
| T-30-06 | Tampering | forged / stale POST to resend a `cancelada` divulgação | medium | mitigate | `#resend` checks `if @divulgacao.status_cancelada?` first → `flash[:alert]` + redirect, before any row mutation or enqueue. Test asserts `assert_no_enqueued_jobs` and an unchanged row. |
| T-30-07 | Spoofing / CSRF | cross-site POST to `resend` | low | mitigate | Rails default `protect_from_forgery` (authenticity token) inherited from `ApplicationController`; `button_to` emits the token; the admin auth harness rejects tokenless / session-less requests. No change required. |
| T-30-08 | Denial of Service | repeated resends flooding the client's WhatsApp number | medium | mitigate | `#resend` only re-enqueues the Phase 29 `Whatsapp::SendToGroupJob` (no synchronous send); that job's atomic claim + `limits_concurrency to: 1, key: instance_id` serialize all sends for the instance, and the control is per-row + `turbo_confirm` friction. No mass-resend endpoint (deferred). Residual is accepted — the deliberate per-group friction is the design (REQUIREMENTS.md "Out of Scope": no 'send to all groups' button). |
| T-30-09 | Tampering | `#resend` reopening `concluida → em_andamento` leaving a stuck badge | low | mitigate | The reopen is paired with an immediate `perform_later`; Phase 29 `finalize_divulgacao_if_done` re-closes the divulgação when the row leaves `pendente` again. The `_status_badge` follows live via the 30-01 `Divulgacao#broadcast_status` callback. |
