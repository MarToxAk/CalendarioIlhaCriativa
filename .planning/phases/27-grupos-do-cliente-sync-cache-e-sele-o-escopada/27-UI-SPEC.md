# Phase 27 — UI Design Contract

> trigger in the Phase 26 panel, the cached-groups page (`admin/clients/:client_id/whatsapp_groups`),
> and the reusable scoped group-picker partial that Phase 28 (Divulgação) will embed.
> Generated by gsd-ui-researcher. All user-facing copy is Brazilian Portuguese (pt-BR).
>
> **This phase inherits Phase 26's design contract verbatim** (`.planning/phases/26-.../26-UI-SPEC.md`).
> Spacing scale, typography pair, the 60/30/10 color split, badge pill shape, card shell,
> table shell, empty-state block, toast, flash banner and secondary/primary button classes
> are all reused **unchanged**. This document only specifies what Phase 27 *adds*.

### Sync trigger + feedback mechanism (Claude's discretion — **locked here**)

**Trigger:** `button_to "Sincronizar grupos"` → `POST sync_admin_client_whatsapp_groups_path(client)` (a `collection` route on the nested `whatsapp_groups` resource). Controller:
1. Loads `@client.whatsapp_instance`. If `nil` or not `connected?` → `redirect_back` with `flash[:alert]` (copy above); **does not enqueue**.
2. Else `Whatsapp::SyncGroupsJob.perform_later(instance)` → `redirect_to admin_client_whatsapp_groups_path(@client), notice: "Sincronização iniciada. Os grupos aparecem aqui em instantes."`

The button carries `data: { turbo_submits_with: "Sincronizando…" }` for immediate disabled + label-swap during the request (mirrors Phase 26 "Verificando…"). It renders `disabled` whenever the instance is absent or not connected.

**In-progress → completion:** `group_sync_controller.js` (Stimulus) on the groups page, modeled on Phase 26's `qr_pairing_controller.js`:
- Values: `statusUrlValue` → `GET sync_status_admin_client_whatsapp_groups_path` returning `{ syncing: bool, synced_at: iso8601|null, error: string|null, count: int }`; `sinceValue` → the `groups_synced_at` ISO string rendered at page load.
- On `connect`, if `syncing` is true or a `notice` flash is present: poll every **3s**, cap **~20 cycles (~60s)**.
- `synced_at` advances past `sinceValue` → stop; fire success toast `Grupos sincronizados.`; `Turbo.visit(window.location, { action: "replace" })` to re-render the list with fresh rows and count.
- `error` becomes non-null → stop; fire the error toast; reveal the inline error box (copy chosen by `error` value); re-enable the button.
- cycle cap reached → stop; show the `text-sm text-slate-500` timeout note + an `Atualizar` link (`text-[#0F7949] hover:underline`).
- The controller **never** writes group `subject`, `remote_jid` or any payload to `console` (INFRA-04).

A visually-hidden `aria-live="polite"` span mirrors the status text ("Sincronizando grupos…", "Grupos sincronizados.") for screen readers.

### Scoped picker partial — visual contract for Phase 28

- Path: `app/views/admin/whatsapp_groups/_picker.html.erb`. Locals: `client:` (required), `selected_ids:` (default `[]`), `field_name:` (default `nil`).
- Options come **only** from `client.whatsapp_instance.whatsapp_groups.where(active: true)` — server-side, always. Inactive groups are **excluded entirely** from the picker (they appear only in the read-only inactive section of the Phase 27 index, never as an option).
- A submitted `whatsapp_group_id` outside that scope raises `ActiveRecord::RecordNotFound` → 404, no existence leak (SC5 — same pattern as `@client.artes.find`). The partial never renders a foreign id, so there is nothing to tamper with client-side.
- Phase 27 renders the partial with `field_name: nil` → checkboxes are `disabled` and carry no `name` (the page proves the scope resolves correctly without persisting anything).
- Phase 28 renders it with `field_name: "divulgacao[whatsapp_group_ids][]"` and a real `selected_ids` → the same rows become live checkboxes, plus the select-all row and the `{N} de {M} grupos selecionados` counter appear.
- Each row shows the `announce` badge inline (same amber pill) so the admin sees "só admins enviam" **before** choosing (GRUPO-04 / SC3).
- Empty picker (zero active groups) renders the "Nenhum grupo ativo para selecionar…" line, not an empty fieldset.
