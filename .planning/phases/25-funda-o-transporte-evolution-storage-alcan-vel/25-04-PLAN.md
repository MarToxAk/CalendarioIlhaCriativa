<objective>
Close INFRA-01: migrate the existing local blobs to MinIO with no arte losing its file, and prove — from outside the LAN — that the Evolution host can actually download the media.

The blob migration is an idempotent rake task (D-05) covering all pre-existing local attachments (~21 MB, ~13 files — re-count at run time; D-04). It also backfills `active_storage_blobs.service_name` for rows the old single-service setup left as NULL or `"local"` (Pitfall 6).

The verification is the whole point of the phase's SC1: a real `curl -I` of a freshly minted presigned URL from a machine that is NOT `192.168.3.203` must return 200 with the right content-type. And per D-12, this plan also confirms app ↔ Evolution reachability both ways (outbound read + inbound `/up`) as the deploy-side check — the actual webhook receiver stays in phase 26.

Purpose: INFRA-01 (done, not just configured) + EVO-01 (deploy-side reachability). Depends on plan 02 (the `amazon` service + `local` source) and plan 03 (a deployed public host + reverse proxy).

Output: `lib/tasks/storage_migration.rake` and a recorded outside-LAN reachability result.

Not autonomous: Task 2's reachability proof is gated on out-of-band human input the executor cannot self-run — an outside-`192.168.3.203` `curl -I` of a presigned URL, and a `curl` of `/up` from the Evolution host. The plan pauses at those `<verify><human-check>` steps for the pasted results. `autonomous: false` keeps this consistent with 25-03 (which also carries a gate); Task 2 is left as `type="auto"` because it also performs real work (running the migration on the deployed host, minting the probe URL), so a pure checkpoint task would not fit.
