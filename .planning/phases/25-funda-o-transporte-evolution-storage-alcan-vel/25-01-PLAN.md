<objective>
Build the single HTTP seam between this app and the agency's real Evolution host, and prove it end to end.

`Evolution::Client` is a PORO (mirrors `Api::JwtService`) that is the *only* place in the codebase that speaks HTTP to Evolution — for every phase 25–30. It carries an explicit `apikey` header, explicit open/write/read timeouts, and a 4-class error taxonomy (`Transient` / `Permanent` / `Unknown` / `NotConnected`) plus a `ConfigurationError`. No `Faraday::Error` and no raw HTTP status ever escapes it.

The plan also removes the orphaned `good_job` gem (INFRA-05) so the bundle has exactly one queue adapter, and adds `:apikey` / `:hash` to `filter_parameters` so the client's request logging can never leak the global key.

Purpose: EVO-01/02/03 + INFRA-05. This is the milestone's highest-value de-risking work — if the contract is wrong every later phase breaks. The read path is verified against `whatsapp.bomcustoilhabela.com.br` and the observed shape is written into `.planning/notes/evolution-contract.md` before any downstream code depends on it.

Output: `app/services/evolution/{client,errors}.rb`, `config/initializers/evolution.rb`, an updated `filter_parameter_logging.rb`, a `Gemfile` with `+faraday` / `-good_job`, a minitest file, and appended authenticated deltas in `evolution-contract.md`.
