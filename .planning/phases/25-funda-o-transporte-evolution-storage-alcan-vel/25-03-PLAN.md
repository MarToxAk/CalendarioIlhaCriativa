<objective>
Stand up the production topology D-09 added to this phase: the Rails app deployed to the public host, co-located with Evolution + MinIO (D-11), with a dedicated jobs worker and TLS.

The existing `docker-compose.yml` has only `db` + `web` — no jobs service (so nothing scheduled would ever run in production) and no TLS termination. This plan adds a `jobs` service running `bin/jobs`, pins `TZ` on both services, wires `production.rb` for the MinIO service + SSL + a Host allow-list, adds a reverse proxy, and puts the Evolution + MinIO secrets into `config/credentials.yml.enc`.

The deploy tool (docker compose vs the scaffolded Kamal) is CONTEXT.md D-10 by interpretation and RESEARCH Open Question 1's "first planning question" — Task 1 is a `checkpoint:decision` to confirm it before the topology is written.

Purpose: INFRA-01 (production storage reachable by construction), INFRA-03 (container `TZ`). The webhook receiver stays in phase 26 (D-12) — this plan only makes app ↔ Evolution reachability possible; plan 04 proves it.

Output: a `jobs` service + `TZ` in `docker-compose.yml`, an SSL-and-hosts `production.rb`, a `deploy/Caddyfile` (tool-dependent), documented `.env.example` keys, and `evolution:` / `aws:` entries in `config/credentials.yml.enc`.
</objective>
