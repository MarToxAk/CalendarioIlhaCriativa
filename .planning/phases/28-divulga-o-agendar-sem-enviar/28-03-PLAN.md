<objective>
Give the admin the two things they need to see before confirming: an exact
preview of what will be posted (media + verbatim caption) and a human duration
estimate for the selected number of groups (DIVU-06, DIVU-07). Wire the three
small Stimulus controllers that make the single-page form live (preview toggle,
estimate recompute, picker select-all/counter) and register the delay-range
env-var contract phase 29 will own.

Purpose: The preview is the anti-"content the client did not approve" guarantee
— the caption goes verbatim, no spinning, no placeholder. The estimate turns
"20 groups" into "≈ 8–14 min" so the admin schedules with the pacing cost in
view. Neither touches a send path.

Output: `_preview.html.erb`, `divulgacao_duration_estimate` helper +
`SEND_DELAY_MIN`/`MAX` constants, three Stimulus controllers, the estimate +
preview blocks + `data-action` wiring on `new.html.erb`, `.env.example` entries.

## API coverage note

No external API. The estimate is pure arithmetic; the preview streams an
existing blob. The Evolution send surface is 100% deferred to phase 29. No
COVERAGE.md is produced.

## Cross-phase contract (phase 29 / ENVIO-02 must honor)

The inter-group delay range is read here from `WHATSAPP_SEND_DELAY_MIN_SECONDS`
/ `WHATSAPP_SEND_DELAY_MAX_SECONDS` (seconds, integer), fallback `25` / `45`.
These names have no repo precedent (RESEARCH Assumption A2) — phase 29 owns the
canonical read. The read lives in exactly one place (`Divulgacao::SEND_DELAY_MIN`
/ `SEND_DELAY_MAX`) so a phase-29 rename is a one-line change plus `.env.example`.
</objective>
