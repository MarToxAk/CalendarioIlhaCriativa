# Phase 28 — UI Design Contract

> Visual and interaction contract for the **Divulgação — Agendar sem Enviar** surfaces:
> the single-page schedule form (`admin/clients/:client_id/divulgacoes/new`), the
> divulgações list (`divulgacoes#index` **and** a mirror section on `admin/clients#show`),
> and the divulgação detail page (`divulgacoes#show`) with its per-group rows and the
> "Cancelar divulgação" action. All user-facing copy is Brazilian Portuguese (pt-BR).
> Generated by gsd-ui-researcher.
>
> **This phase inherits the Phase 26 → Phase 27 design contract verbatim**
> (`.planning/phases/27-.../27-UI-SPEC.md`). Spacing scale, the 400/500/600 typography set,
> the 60/30/10 color split, card shell, section heading, page `<h1>`, primary/secondary/
> destructive button classes, badge-pill shape, empty-state block, flash banner, toast, and
> the `_picker.html.erb` partial are all reused **unchanged**. This document specifies only
> what Phase 28 *adds*: the schedule form, the preview card, the duration estimate, the
> per-group status rows, and the cancel action.
>
> **Deliberate scope stop:** nothing here sends, enqueues, or talks to Evolution. No live/
> realtime UI (that is Phase 30). The only client-side JS is two small Stimulus controllers
> (duration estimate + preview toggle) and the picker select-all/counter wiring.

## Spacing Scale

Inherited from Phases 26–27 (Tailwind default 4px grid). **This phase adds no new tokens.**

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px (`gap-1`, `p-1`) | Badge inner glyph gap (`●` → label) |
| sm | 8px (`gap-2`, `space-y-2`, `mb-2`) | Preview-header → media gap, status-line stacks |
| md | 12px (`gap-3`, `py-3`, `pb-3`) | Checkbox → label gap, `<label>` row vertical padding, section-heading `pb-3`, per-group row padding |
| md+ | 16px (`px-4`, `mb-4`, `space-y-4`) | Form field vertical rhythm (`mb-4` between fields), `<label>` row horizontal padding, error-box padding-adjacent gap |
| lg | 24px (`p-6`, `mb-6`) | Card interior padding (list + `show` sections), page-header margin |
| xl | 32px (`p-8`, `py-8`) | Schedule-form card interior padding; `<main>` vertical padding (layout-owned) |
| 3xl | 64px (`py-16`) | Full-page empty-state vertical padding (matches `artes/index`, `approvals/index`) |

**Checkbox sizing:** `h-4 w-4` (16px), on the 4px grid. Picker `<label>` row is `flex items-center gap-3 py-3 px-4` → row height ≈ 44px, meeting the touch-target floor without a special token (inherited from Phase 27).

**Interactive control heights (inherited, all ×4):** `h-8` (small button), `h-9` (secondary / destructive button), `h-10` (primary submit), `h-11` (text/select/datetime inputs — matches `clients/_form`, `clients/show` fields).

**Exceptions (inherited from Phases 26–27, reuse-only — not expanded here):**
- `mb-1.5` (6px) label-to-input gap on form fields (matches `admin/artes/_form`).
- `gap-1.5` (6px) for inline text affordances; `py-0.5` (2px) compact micro-badge.
- Scroll containers use sizing utilities, not spacing tokens: the in-form group list caps at `max-h-[380px] overflow-y-auto`; the caption preview caps at `max-h-64 overflow-y-auto`. These constrain overflow (see UI Considerations), they are not new spacing steps.

| `announce` badge (inherited) | `Só admins enviam` · `title="Neste grupo, apenas administradores podem enviar mensagens."` |
| Select-all checkbox (visually-hidden label, inherited) | `Selecionar todos os grupos ativos` |

**Copy note — the only destructive action is "Cancelar divulgação".** It uses `turbo_confirm`

### Stimulus controllers (Claude's discretion — **locked here**)

**`divulgacao_estimate_controller.js`** — scoped to the `<form>`.
- `static targets = ["text"]`; `static values = { min: Number, max: Number }` read from `data-divulgacao-estimate-min-value` / `-max-value` on the picker container (server-injected from `Divulgacao::SEND_DELAY_MIN` / `SEND_DELAY_MAX`).
- Fallback delay constants (CONTEXT-resolved): `WHATSAPP_SEND_DELAY_MIN_SECONDS=25`, `WHATSAPP_SEND_DELAY_MAX_SECONDS=45`. Phase 29 owns the canonical read; Phase 28 has a read-only helper with this fallback.
- `connect()` calls `recompute()`. `recompute()` counts `input[type="checkbox"][name="divulgacao[whatsapp_group_ids][]"]:checked`; if 0 → text `—`; else `lo = ceil(n*min/60)`, `hi = ceil(n*max/60)`, text `≈ lo–hi min para n grupos` (or `≈ lo min para n grupos` when `lo == hi`).
- Wired via `data-action="change->divulgacao-estimate#recompute"` on the picker container.
- **No-JS fallback / source of truth:** `divulgacao_duration_estimate(n, min:, max:)` helper renders the same string on `show` and on any server re-render.

**`divulgacao_preview_controller.js`** — scoped to the `<form>`.
- `static targets = ["pane", "placeholder"]`. Each `pane` carries `data-arte-id`.
- `show()` (bound to the arte `<select>` `change`) hides every `pane` + the `placeholder`, then unhides the `pane` whose `data-arte-id` matches the select value; if the select is on the prompt, show the `placeholder` instead.
- `connect()` runs `show()` once (handles the pre-selected / single-arte case).
- If only one approved arte exists, the view may render its `_preview` directly with no panes — the controller then just no-ops.

**`picker_controller.js`** — scoped to the `_picker.html.erb` fieldset (reusable, ships with the partial).
- Wires the `data-picker-select-all` checkbox (toggles every active-group checkbox) and rewrites the `data-picker-counter` element to `{N} de {M} grupos selecionados` on any `change`.
- Dispatches a bubbling `change` so `divulgacao-estimate` recomputes after select-all.
- Phase 27 shipped these DOM markers unwired; Phase 28 is where they become live.

### Server-side interaction rules (not UI, but binding on the executor)

- `create`: re-resolve `arte_id` via `@client.artes.find`, every group id via `@client.whatsapp_instance.whatsapp_groups.where(active: true).find(ids)` → `RecordNotFound` rescued to `flash.now[:alert]` + `render :new, status: :unprocessable_entity`. Build `divulgacao_grupos` as association records in the single `@divulgacao.save` transaction, snapshotting `group_name = g.display_name` and `remote_jid = g.remote_jid` at build time (DIVU-09).
- `scheduled_for`: assign the raw `"YYYY-MM-DDTHH:MM"` string straight to the attribute (time-zone-aware cast through `Time.zone` = Brasília). Never `Time.parse` the param.
- `cancel`: dedicated `patch :cancel` member route → sets `status: :cancelada` only when currently `agendada`; `redirect_to` the `show` page with the cancel `notice`. No `destroy`.
- Preview media: `rails_storage_proxy_path` (Rails streams the blob) — not `url_for` / presigned — so the preview does not expire while the admin fills the form.
