## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Retry/discard decision → DB state | The error taxonomy is the ONLY thing standing between "a network blip" and "a group silently never receives its arte, or receives it twice." Every branch is now covered by a dedicated test in this plan. |
| Concurrency semaphore (solid_queue) → per-instance serialization | `limits_concurrency` writes to `solid_queue_semaphores` (DB-backed) — the key MUST resolve to the correct `WhatsappInstance` or two sends from different clients' instances could serialize against each other unnecessarily (availability bug, not a security one) or — if the key resolved to the WRONG instance due to a data bug — two sends from the SAME instance could run in parallel (the actual ENVIO-09 threat). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-29-05 | Tampering | Atomic claim vs `retry_on(Transient)` interaction | high | mitigate | The claim-then-send ordering (plan 29-01) combined with an unconditional `retry_on` would silently defeat every retry after the first attempt (claim already flipped to `enviado`, second attempt's claim returns 0 rows, no-op forever — a group that should have retried and sent never does). Fixed in this plan by reverting the claim to `pendente` inside a `rescue Evolution::Errors::Transient` before re-raising, proven by a dedicated two-call test (Task 1). |
| T-29-06 | Repudiation / Tampering | Double-send under retry/duplicate dispatch | high | mitigate | ENVIO-04's core guarantee — proven under 4 adversarial scenarios in Task 2 (pre-set terminal status, double `perform_now`, double `perform_later`+drain, and the raw SQL claim race) — Evolution is provably called at most once per group regardless of execution order or count. |
| T-29-07 | Information Disclosure | `error_code` truncation across all discard branches | medium | mitigate | `ERROR_CODE_MAX_LENGTH = 500` applied uniformly via `mark_falhou`/`mark_incerto` class helpers — a single code path, not per-branch discipline that could be forgotten on one handler (Pitfall 6). Message source is always `Evolution::Client`'s already-normalized `err.message` (never raw response body/headers/apikey) or a static internal string. |
