  <how-to-verify>
    Execute os seguintes passos no terminal:

    1. Abrir o editor de credentials:
       ```
       bin/rails credentials:edit
       ```
       (Abre o arquivo decriptado em $EDITOR)

    2. Adicionar as seguintes chaves ao arquivo (no nível raiz, abaixo das entradas existentes):

       ```yaml
       jwt_secret: [gere com: bin/rails runner "puts SecureRandom.hex(32)"]

       api:
         ai_key: [gere com: bin/rails runner "puts 'ak_' + SecureRandom.hex(32)"]
       ```

       Para gerar os valores antes de editar:
       ```
       bin/rails runner "puts SecureRandom.hex(32)"
       bin/rails runner "puts 'ak_' + SecureRandom.hex(32)"
       ```

    3. Salvar e fechar o editor (credentials.yml.enc será regravado automaticamente).

    4. Verificar que as chaves estão disponíveis:
       ```
       bin/rails runner "puts Rails.application.credentials.jwt_secret.present?"
       bin/rails runner "puts Rails.application.credentials.dig(:api, :ai_key)&.start_with?('ak_')"
       ```
       Ambos devem imprimir `true`.

    **Nota:** Se o ambiente de produção usa `RAILS_MASTER_KEY` como ENV var em vez de `config/master.key`, garantir que a mesma master key está configurada. O fallback `ENV["JWT_SECRET"]` e `ENV["AI_API_KEY"]` pode ser usado em desenvolvimento se preferir não editar as credentials.

## Trust Boundaries

| Boundary | Descrição |
|----------|-----------|
| config/master.key → credentials.yml.enc | Master key não vai para o repositório; secrets são protegidos por encryption em repouso |
| Test env → credenciais reais | Testes não devem usar o jwt_secret de produção; ENV["JWT_SECRET"] pode ser setado no test env |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-20 | Information Disclosure | jwt_secret ou ai_key commitado em texto claro no repositório | mitigate | Chaves adicionadas via `bin/rails credentials:edit` ao arquivo encriptado credentials.yml.enc; config/master.key está no .gitignore do projeto |
| T-21-21 | Elevation of Privilege | Teste usa JWT gerado com segredo de produção vazado | mitigate | Em ambiente de teste, usar ENV["JWT_SECRET"] com valor aleatório de test setup, ou gerar token via JwtService em test helper — nunca hardcodar o segredo de produção em teste |
| T-21-22 | Repudiation | Ausência de cobertura de testes para cenários de auth failure | mitigate | Arquivos de teste cobrem explicitamente: credenciais inválidas (401), token ausente (401), scope errado (401) |
| T-21-SC | Tampering | Instalação adicional de gems neste plano | accept | Plano 05 não instala gems novas — threat SC encerrado no plano 01 |
</threat_model>
