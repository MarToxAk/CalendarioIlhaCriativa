    Criar `app/services/api/jwt_service.rb` com o módulo `Api` contendo a classe `JwtService` e dois erros de domínio dentro de `module Api::Errors`:
    - `Api::Errors::TokenExpired < StandardError`
    - `Api::Errors::TokenInvalid < StandardError`

    A classe `Api::JwtService` deve ter:
    - Constante `ALGORITHM = "HS256".freeze` — nunca dinâmica (PATTERNS.md Critical Constraints #2)
    - Constante `DEFAULT_EXPIRY` lendo `(Rails.application.credentials.jwt_expiry_hours || 24).hours` (per D-04 e RESEARCH.md Open Questions #3)
    - Método de classe `encode(payload, expiry: DEFAULT_EXPIRY)`: mescla `iat: Time.now.to_i` e `exp: expiry.from_now.to_i` ao payload, chama `JWT.encode(full_payload, secret, ALGORITHM)`, retorna a string do token
    - Método de classe `decode(token)`: chama `JWT.decode(token, secret, true, { algorithm: ALGORITHM, verify_exp: true })`, retorna `decoded.first.with_indifferent_access`. Rescue `JWT::ExpiredSignature` → re-raise como `Api::Errors::TokenExpired`. Rescue `JWT::DecodeError` → re-raise como `Api::Errors::TokenInvalid`
    - Método privado de classe `secret`: `Rails.application.credentials.jwt_secret || ENV.fetch("JWT_SECRET") { raise "JWT_SECRET not configured" }`

    Não usar `JWT::Token` nem `JWT::EncodedToken` (API nova da v3; desnecessária para HS256 simples — RESEARCH.md State of the Art).
    Não colocar o segredo em constante de classe (lê sempre de credentials/ENV para compatibilidade com rotação).
    Os domain errors devem ser definidos ANTES da classe JwtService no mesmo arquivo para garantir que estão disponíveis no rescue interno.

<threat_model>
## Trust Boundaries

| Boundary | Descrição |
|----------|-----------|
| Caller → JwtService.decode | Token externo pode ter sido forjado, expirado ou com alg:none |
| JwtService → Rails.credentials | Segredo nunca pode estar hardcoded; lido em runtime de credentials ou ENV |
| Rails router → Api controllers | defaults: { format: :json } garante que respostas são JSON sem negociação de tipo |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-04 | Tampering | JWT.decode sem algorithm especificado | mitigate | ALGORITHM = "HS256".freeze como constante em JwtService; passado explicitamente em cada chamada JWT.decode como `{ algorithm: ALGORITHM }` |
| T-21-05 | Elevation of Privilege | Token JWT expirado ainda aceito | mitigate | `verify_exp: true` passado explicitamente no hash de opções do JWT.decode; gem v3.2 respeita este flag e lança JWT::ExpiredSignature |
| T-21-06 | Information Disclosure | JWT_SECRET hardcoded ou em variável de instância de classe | mitigate | Método `secret` lê de `Rails.application.credentials.jwt_secret || ENV.fetch("JWT_SECRET")` — nunca como constante da classe; método marcado `private_class_method` |
| T-21-07 | Elevation of Privilege | API controller herda de ApplicationController (inclui auth cookie) | mitigate | Api::V1::BaseController herda de ActionController::API — sem CSRF, sem cookies, sem Authentication concern |
| T-21-08 | Information Disclosure | Erros de 500 expondo stack traces para clientes API | mitigate | rescue_from centralizado em BaseController cobre RecordNotFound, RecordInvalid e ParameterMissing — retorna envelope estruturado em vez de HTML de erro |
</threat_model>
