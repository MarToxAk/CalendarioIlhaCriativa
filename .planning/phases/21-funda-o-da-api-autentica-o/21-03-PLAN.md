<threat_model>
## Trust Boundaries

| Boundary | Descrição |
|----------|-----------|
| Client (mobile) → POST /api/v1/admin/session | Parâmetros email + password chegam não-autenticados; podem ser forjados |
| Client (mobile) → POST /api/v1/client/session | Parâmetros access_token + password chegam não-autenticados |
| SessionsController → JwtService | Token emitido deve usar claims corretos — falha aqui cria tokens com escopo errado |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-09 | Information Disclosure | Enumeração de usuário via resposta diferente para "email não existe" vs "senha errada" | mitigate | `invalid_credentials` único para ambos os casos; User.find_by retorna nil silenciosamente; `&.authenticate` retorna false — fluxo unificado |
| T-21-10 | Information Disclosure | Enumeração de cliente via resposta diferente para "inativo" vs "senha errada" | mitigate | Verificar `active?` depois de `authenticate` e usar o mesmo `invalid_credentials` — não revelar status de inatividade |
| T-21-11 | Elevation of Privilege | Login endpoint com before_action de autenticação herdado | mitigate | SessionsControllers herdam de `Api::V1::BaseController` (não do namespace base_controller) — sem guard de auth herdado |
| T-21-12 | Repudiation | Brute force nos endpoints de login | mitigate | Throttles rack-attack adicionados no plano 01 (api/admin_login_by_ip, api/client_login_by_ip); resposta 429 em JSON já configurada |
| T-21-13 | Tampering | Claim `scope` errado no JWT emitido (ex: cliente recebe scope:"admin") | mitigate | Scope hardcoded como string literal em cada controller (`"admin"` em admin/sessions, `"client"` em client/sessions) — não derivado de parâmetro externo |
</threat_model>
