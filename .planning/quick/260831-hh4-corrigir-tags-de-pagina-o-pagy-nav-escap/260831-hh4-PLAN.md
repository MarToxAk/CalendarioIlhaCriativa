<objective>
Corrigir a paginação (`pagy_nav`) aparecendo como marcação HTML crua e escapada
("`&lt;nav class="pagy nav"...`") no rodapé das telas de grupos do WhatsApp e de
aprovações, em vez de renderizar como navegação clicável.

**Causa raiz confirmada empiricamente nesta sessão:** `Pagy::Frontend#pagy_nav`
(gem `pagy` 9.4.0) monta a string de navegação com um literal Ruby comum
(`%(<nav ...>)`), sem nunca chamar `.html_safe`. `ActionView::OutputBuffer#<<`
(usado por `<%= %>` via `.append=`) checa `value.html_safe?` e ESCAPA qualquer
valor que não seja explicitamente seguro — por isso `<%= pagy_nav(pagy) %>`
produz `&lt;nav...` em vez de `<nav...>`. O sibling correto já existe no próprio
repo: `app/views/admin/divulcacoes/index.html.erb:81` usa `<%== pagy_nav(@pagy) %>`
(tag Erubi para saída não-escapada), que é o padrão certo — comprovado nesta
sessão renderizando o partial de verdade via `ApplicationController.render` com
o client 31 (64 grupos reais sincronizados): com `<%==` o HTML sai cru
(`<nav class="pagy nav"...`); com `<%=` sairia escapado.

Purpose: alinhar os dois call-sites que ainda usam `<%=` ao padrão já correto
usado em `divulgacoes/index.html.erb`.
Output: `pagy_nav` renderiza como navegação HTML real nas 3 telas paginadas do
admin (divulgações, grupos do WhatsApp, aprovações).
</objective>
