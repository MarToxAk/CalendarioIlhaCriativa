**Status:** ✅ SHIPPED 2026-06-13

## Overview

API JSON REST versionada (`/api/v1/`) para suportar um app mobile (admin + cliente) e um agente de IA. Três modos de autenticação: JWT para admin, token do portal como Bearer para cliente, e API key dedicada para IA.

**Key deliverables:**
- `JwtService` com encode/decode e algoritmo HS256 fixo (defesa alg:none)

## Milestone Summary

**Key Accomplishments:**

1. API REST versionada em `/api/v1/` com três namespaces isolados (admin/client/ai) e três modos de autenticação distintos
2. JwtService PORO com HS256 fixo, envelope `{ data, meta, errors }` consistente em todos os endpoints
3. 5 endpoints admin (clients + artes + approval_responses) com upload via ActiveStorage
4. 3 endpoints cliente com isolamento cross-client garantido por design (associação eager-scoped)
5. 3 endpoints IA (list, create, summary) com rate limiting Rack::Attack dual-layer (by key + by IP)
6. 20/20 requisitos implementados; 2 itens UAT/verification do Phase 23 deferidos (execução de testes de integração)

**Key Decisions:**

- `Api::V1::BaseController < ActionController::API` (não ApplicationController) — isola CSRF/cookies/Session do auth web
- Cliente usa `access_token + senha → JWT` (não token direto) — access_token é semi-público (viaja no link do calendário)
- JWT único 24h sem refresh token — alinha com DNA enxuto do projeto
- Campo de login admin é `email` (mapeia para `User#email_address`) — contrato fixo da API
- `jwt_secret` e `api.ai_key` em Rails credentials (não ENV) — production-safe, cifrado em repouso
- Throttle duplo para AI namespace: by key (60/min) + by IP (30/min fallback) — cobre requisições sem auth

**Tech Debt Incurred:**

- Phase 23 UAT e VERIFICATION marcados como `human_needed` — aguardam execução manual dos testes de integração
- `external_url` no modelo Arte não tem validação de formato URI (identificado em CR-01 INFO; fix é adicionar `validates :external_url, format: /\Ahttps?:\/\//`)
- `rack_attack_test.rb` sem `# frozen_string_literal: true` (mínimo)
