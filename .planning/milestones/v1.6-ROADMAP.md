# Milestone v1.6: API JSON

**Status:** 🟡 Em planejamento
**Fases previstas:** 21–24
**Requisitos:** 16 (AUTH-01..05, APIADM-01..05, APICLI-01..03, APIAI-01..03, INFAPI-01..04)

## Overview

Expõe uma API JSON REST versionada para suportar um app mobile (admin + cliente) e um agente de IA. Usa três modos de autenticação: JWT para admin, token do portal como Bearer para cliente, e API key dedicada para IA.

---

## Phases

### Phase 21: Fundação da API + Autenticação

**Goal**: API versionada em `/api/v1/` com os três modos de auth funcionando e middleware de autenticação distinguindo cada tipo de consumidor

**Requirements**: AUTH-01, AUTH-02, AUTH-03, AUTH-04, AUTH-05, INFAPI-01, INFAPI-02, INFAPI-03

---

### Phase 22: Endpoints Admin

**Goal**: Admin mobile consegue listar clientes, criar artes e consultar histórico de aprovações via API

**Requirements**: APIADM-01, APIADM-02, APIADM-03, APIADM-04, APIADM-05
**Depends on**: Phase 21

---

### Phase 23: Endpoints Cliente

**Goal**: Cliente mobile consegue ver suas artes pendentes e submeter resposta de aprovação via API

**Requirements**: APICLI-01, APICLI-02, APICLI-03
**Depends on**: Phase 21

---

### Phase 24: Endpoints IA + Rate Limiting

**Goal**: IA consegue listar aprovações, inserir artes e ler resumos; API tem rate limiting por key/token

**Requirements**: APIAI-01, APIAI-02, APIAI-03, INFAPI-04
**Depends on**: Phase 21, 22

---

## Notas de Design

- Ver `.planning/notes/api-auth-strategy.md` para decisões de autenticação
- Fases 22 e 23 podem ser executadas em paralelo após a Phase 21 (fundação + auth)
- Upload de imagens na Phase 22 (APIADM-04) reusa Active Storage já configurado
