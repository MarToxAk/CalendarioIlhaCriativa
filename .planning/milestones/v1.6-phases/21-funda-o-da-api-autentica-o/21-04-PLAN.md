    **app/controllers/api/v1/admin/base_controller.rb:** Criar com a classe `Api::V1::Admin::BaseController < Api::V1::BaseController`. Adicionar `before_action :authenticate_admin_jwt!`.

    O método privado `authenticate_admin_jwt!`:
    1. Chama `bearer_token` para extrair o token do header `Authorization`
    2. Se token ausente → `render_unauthorized`
    3. Se token começa com `"ak_"` (prefixo de API key da IA) → `render_unauthorized` (API key não é JWT de admin — D-07)
    4. Decodifica com `Api::JwtService.decode(token)`
    5. Se `claims[:scope] != "admin"` → `render_unauthorized`
    6. Busca `@current_user = User.find_by(id: claims[:sub])`
    7. Se `@current_user` nil → `render_unauthorized`
    8. Rescue `Api::Errors::TokenExpired, Api::Errors::TokenInvalid` → `render_unauthorized`

    O método privado `bearer_token`:
    `request.headers["Authorization"]&.delete_prefix("Bearer ")&.strip.presence`

    O método privado `render_unauthorized`:
    `render_error(code: "unauthorized", detail: "Autenticação inválida ou expirada", status: :unauthorized)`

    **app/controllers/api/v1/client/base_controller.rb:** Criar com a classe `Api::V1::Client::BaseController < Api::V1::BaseController`. Adicionar `before_action :authenticate_client_jwt!`.

    O método privado `authenticate_client_jwt!` segue o mesmo fluxo mas:
    - Não rejeita prefixo `ak_` explicitamente (qualquer token não-JWT de cliente resulta em `TokenInvalid` no decode)
    - Verifica `claims[:scope] == "client"` (não `"admin"`)
    - Busca `@current_client = Client.find_by(id: claims[:sub])`
    - Verifica `@current_client&.active?` — se inativo → `render_unauthorized`

    Os métodos `bearer_token` e `render_unauthorized` são duplicados em cada controller (não extrair para concern agora — os namespaces devem ser independentes para facilitar auditoria per D-06).

<threat_model>
## Trust Boundaries

| Boundary | Descrição |
|----------|-----------|
| Authorization header → authenticate_admin_jwt! | Token pode ser expirado, forjado, de escopo errado ou com alg:none |
| Authorization header → authenticate_client_jwt! | Idem; adiciona verificação de cliente ativo |
| Authorization header → authenticate_ai_key! | API key opaca; comparação deve ser em tempo constante |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-14 | Elevation of Privilege | Token JWT de cliente usado em endpoint admin | mitigate | `authenticate_admin_jwt!` verifica `claims[:scope] == "admin"` — scope incorreto → 401; scope está na assinatura e não pode ser forjado |
| T-21-15 | Elevation of Privilege | Token JWT de admin usado em endpoint cliente | mitigate | `authenticate_client_jwt!` verifica `claims[:scope] == "client"` — idem |
| T-21-16 | Elevation of Privilege | API key da IA usada em endpoint admin ou cliente | mitigate | `authenticate_admin_jwt!` rejeita qualquer token começando com `ak_`; guard JWT de cliente rejeita implicitamente pois ak_ não é JWT decodificável |
| T-21-17 | Information Disclosure | Timing attack na comparação de API key | mitigate | `ActiveSupport::SecurityUtils.secure_compare` — comparação de tempo constante; nunca `==` |
| T-21-18 | Elevation of Privilege | Cliente inativo mantém JWT válido | mitigate | `authenticate_client_jwt!` verifica `client.active?` após decode — cliente desativado recebe 401 mesmo com JWT válido |
| T-21-19 | Elevation of Privilege | API key da IA não configurada → 500 ao invés de 401 | mitigate | `expected` nil → `render_unauthorized` antes do `secure_compare` — credentials ausentes tratadas como auth inválida |
</threat_model>
