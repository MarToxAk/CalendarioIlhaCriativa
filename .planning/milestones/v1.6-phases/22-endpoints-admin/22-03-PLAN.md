## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| multipart request → arte_params | media_file chega como UploadedFile; content_type validation no model é a linha de defesa |
| arte_params → Arte.new | params.permit lista campos explicitamente; admin_reply e outros campos internos não são permitidos |
| apply_filters → AR query | Todos os params passam por guard (enum key? check, Date.strptime rescue) antes de .where |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-10 | Tampering | media_file upload | mitigate | validates :media_file content_type whitelist (jpeg/png/gif/mp4/quicktime) + size < 50MB via active_storage_validations — adicionado ao Arte model nesta fase |
| T-22-11 | Tampering | apply_filters — status enum injection | mitigate | Arte.statuses.key?(params[:status]) guarda antes de .where — evita ArgumentError e injeção de valor não reconhecido pelo enum |
| T-22-12 | Tampering | apply_filters — month SQL injection | mitigate | Date.strptime valida formato antes de gerar range — string inválida lança Date::Error → 400; AR usa parameterized queries para o range |
| T-22-13 | Tampering | arte_params mass assignment | mitigate | params.permit lista explícita; :admin_reply e :status não são permitidos (status vem da lógica de negócio, não da API) |
| T-22-14 | Denial of Service | GET /artes sem filtros | mitigate | per_page_param cap 100 + Pagy — query sempre limita linhas retornadas |
| T-22-15 | Tampering | ActionCable callbacks | accept | Callbacks after_create/update_commit no Arte model permanecem ativos por design — broadcasts são feature intencional, não superfície de ataque |
| T-22-SC | Tampering | npm/pip/cargo installs | accept | Nenhuma gem nova instalada — active_storage_validations já está no Gemfile |
</threat_model>
